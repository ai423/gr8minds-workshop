# רישום אוטומטי לגיליון + מייל אישור

כל מי שמשלם נרשם אוטומטית לגיליון גוגל ומקבל מייל עם פרטי הסדנה.

## למה דרך Apps Script ולא דרך Google Sheets API

כדי לכתוב לגיליון מהשרת דרך ה-API של גוגל צריך service account, קובץ מפתח JSON,
ולשתף איתו את הגיליון. זה אומר מפתח פרטי שמסתובב במשתני סביבה, ועוד חשבון לנהל.

Apps Script יושב בתוך הגיליון עצמו. הוא כותב שורות בלי הרשאות חיצוניות, ושולח
מייל **מהחשבון שלך** בלי SMTP ובלי ספק דיוור. מה שצריך זה כתובת אחת ב-Vercel.

**מגבלה שכדאי להכיר:** חשבון Google Workspace שולח עד 1,500 מיילים ביום דרך
Apps Script (חשבון Gmail רגיל, 100). לסדנאות של 12 מקומות זה לא רלוונטי.

## התקנה, פעם אחת

### 1. גיליון חדש

לפתוח גיליון ריק ב-https://sheets.new ולתת לו שם, למשל "הרשמות לסדנאות".
אין צורך ליצור לשוניות או כותרות, הסקריפט עושה את זה לבד בפעם הראשונה.

### 2. להדביק את הקוד

בגיליון: **Extensions → Apps Script**. למחוק את מה שיש שם, ולהדביק את כל
התוכן של `Code.gs`.

### 3. לקבוע סיסמה משותפת

בשורה הראשונה של הקוד:

```js
const TOKEN = 'שנו-אותי-למחרוזת-אקראית';
```

להחליף במחרוזת אקראית ארוכה. אפשר לייצר אחת בטרמינל:

```bash
openssl rand -hex 24
```

**לשמור אותה בצד**, היא נדרשת בשלב 5. בלי הבדיקה הזאת כל מי שמכיר את כתובת
הסקריפט יכול להוסיף שורות לגיליון.

לשמור את הפרויקט (אייקון הדיסקט).

### 4. לפרוס כאפליקציית ווב

**Deploy → New deployment** → בגלגל השיניים לבחור **Web app**, ואז:

| שדה | ערך |
|---|---|
| Description | GR8MINDS registrations |
| Execute as | **Me** |
| Who has access | **Anyone** |

> "Anyone" נשמע מפחיד, אבל זו הדרך היחידה ששרת חיצוני יוכל לפנות לסקריפט.
> ה-`TOKEN` הוא מה ששומר עליו, ולכן הוא חייב להיות אקראי.

ללחוץ **Deploy**. גוגל תבקש הרשאות בפעם הראשונה: **Review permissions** →
לבחור את החשבון → במסך האזהרה **Advanced** → **Go to (project name)** →
**Allow**. זה נדרש כי הסקריפט שולח מיילים בשמך.

בסוף מתקבלת כתובת בצורה:

```
https://script.google.com/macros/s/AKfycb.../exec
```

**להעתיק אותה.**

### 5. לחבר ל-Vercel

**Settings → Environment Variables**, להוסיף שניים:

| משתנה | ערך |
|---|---|
| `SHEET_WEBHOOK_URL` | הכתובת מהשלב הקודם |
| `SHEET_WEBHOOK_TOKEN` | אותה מחרוזת שקבעת בשלב 3 |

ואז **Redeploy** — משתני סביבה לא נכנסים לפריסה קיימת.

### 6. לבדוק

**בלי לחייב כרטיס:** בעורך Apps Script לבחור למעלה את הפונקציה `testRun`
וללחוץ **Run**. אמורה להיווצר שורה בגיליון, ואמור להגיע אליך מייל.

**מקצה לקצה:** לבצע רכישת בדיקה אמיתית באתר ולוודא ששורה נוספה ושהמייל הגיע.

## איך זה עובד

1. הלקוח משלם בדף המאובטח של קארדקום.
2. קארדקום שולח הודעה ל-`/api/cardcom-webhook`.
3. **הפונקציה לא סומכת על ההודעה.** היא לוקחת ממנה רק את מזהה העסקה ושואלת
   את קארדקום ישירות מה קרה (`LowProfile/GetLpResult`).
4. רק אם קארדקום מאשר שהתשלום עבר, הפרטים נשלחים לסקריפט.
5. הסקריפט מוסיף שורה ושולח את המייל.

**המשמעות:** אי אפשר להירשם בלי לשלם. גם מי שיפנה ישירות לכתובת של הפונקציה
לא ייכנס לגיליון, כי האישור מגיע מקארדקום ולא מהפונה.

## דברים שכבר מטופלים

- **כפילויות.** אם קארדקום שולח את אותה הודעה פעמיים, השורה נרשמת פעם אחת
  (לפי מספר ההזמנה).
- **מייל שנכשל לא מאבד הרשמה.** אם שליחת המייל נופלת, השורה עדיין נרשמת
  ובעמודה "מייל נשלח" מופיעה השגיאה, כדי שאפשר יהיה לשלוח ידנית.
- **סדנה חדשה לא דורשת שינוי.** פרטי הסדנה נשלחים עם כל הרשמה מתוך
  `workshops.js`, אז המייל נשאר נכון גם לסדנאות שיתווספו.
- **תקלה בגיליון לא מבטלת תשלום.** אם הסקריפט לא זמין, התשלום עדיין עובר
  והשגיאה נרשמת בלוגים של Vercel תחת `REGISTRATION NOT RECORDED`.

## לשנות את נוסח המייל

הפונקציה `sendConfirmation` ב-`Code.gs`. לערוך, לשמור, ואז
**Deploy → Manage deployments → עריכה → New version → Deploy**.
בלי גרסה חדשה השינוי לא נכנס לתוקף.
